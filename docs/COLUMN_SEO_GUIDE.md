# コラム運用ガイド（SEO / AIEO / LLMO）

全力ストレッチ岐阜長良店のコラムを「岐阜で一番SEOが強い」水準に育てるための方針・作り方・自動化手順をまとめる。**人が読んでも、Claudeのルーティン（自動生成セッション）が読んでも、そのまま実行できる**ことを目的とする。

---

## 0. 大原則（最初に必ず読む）

1. **量より質。** Googleは2024年以降「スケールされたコンテンツの不正利用（大量生成での順位操作）」を明確にペナルティ対象化。**独自性・実体験・専門性のない記事は書かない**。
2. **健康系＝YMYL寄り。** ストレッチ・身体の情報は E-E-A-T（経験・専門性・権威性・信頼性）の基準が高い。断定的な医療効果を約束しない。強い痛み・しびれは医療機関を案内する（免責は ColumnLayout が自動付与）。
3. **1記事＝1つの検索意図。** キーワードを詰め込まない。1つの悩み・1つの意図に絞って深く答える。
4. **重複を作らない。** 既存記事と同じ意図の記事は書かない（カニバリゼーション回避）。似たテーマは1本に統合し内部リンクで補強。
5. **必ず内部リンク。** 該当する `/symptoms/*` ページと `/reserve`（予約）へ導線を張る＝トピッククラスター化でサイト全体の専門性を底上げ。

---

## 1. 更新頻度

- **推奨：週2〜3本**（例：月・水・金）。立ち上げ期（最初の2〜3ヶ月）はやや多めでも可。ただし**毎回「読む価値のある独自記事」であること**が絶対条件。
- **毎日は非推奨。** 品質が落ちれば健康系では順位下落リスク。頻度より「継続」と「質」。
- ルーティンの cron はこの方針に合わせて設定（初期値：週3・月水金の朝）。

## 2. キーワード選定の仕方

### 2-1. 掛け合わせの型
**ローカル × 症状 × 意図 × 属性/季節** でロングテール（3〜4語）を作る。

- **症状**：肩こり／腰痛／むくみ・冷え／首こり・眼精疲労／猫背・姿勢／自律神経・疲れ・睡眠／スポーツ
- **ローカル**：岐阜市／長良／岐阜＋ランドマーク（ヤマダデンキ テックランド岐阜長良の近く）
- **意図**：原因／対策／セルフストレッチのやり方／頻度／「ストレッチ vs 整体・マッサージ」比較／初めてガイド
- **属性・季節**：デスクワーク／立ち仕事／運転／産後／ゴルフ・ランニング／冬の冷え・むくみ／春の自律神経

### 2-2. 選び方の優先順位
1. **具体的な悩み系ロングテール**を最優先（例「デスクワーク 肩こり ストレッチ 座ったまま」）。競合が弱く成約に近い。
2. **比較・検討系**（例「ストレッチ 整体 違い」）＝来店直前の高意図。ローカル指名を絡める。
3. **地域＋一般**（例「岐阜市 ストレッチ 専門店」）＝指名獲得。無理に詰めず自然に。
4. 検索ボリュームよりも**「うちが一次体験で語れるか」**を重視。語れないテーマは書かない。

### 2-3. やってはいけない
- 既存記事と意図が被るキーワードを新規で狙う（→ 既存を更新して強化する）。
- 1記事に複数の主要キーワードを詰める。
- 数字の水増し（「10選」ありきで内容が薄い）。

## 3. コラムの作り方（構成テンプレート）

### 3-1. AIEO / LLMO を意識した構成
AI検索（SGE等）やLLMに「引用・要約」されやすい形にする。

1. **結論先出し（リード）**：冒頭2〜3文で「答え」を30〜60字で言い切る。LLMはここを引用する。
2. **見出し（h2）は質問形**：ユーザー／音声／AI検索のクエリに一致させる。
   - 例：「デスクワークの肩こりはなぜ起きる？」「1日何回やればいい？」
3. **各セクションは"答え→理由→具体"の順**。一文を簡潔・抽出可能に。曖昧表現を避け事実ベース。
4. **手順は番号付き（h3 or ol）**。「◯秒／◯回」など具体的に。
5. **末尾に FAQ 3〜5問**（後述の `faq` プロップ）＝FAQPage構造化データでリッチリザルト＆LLM抽出に強い。
6. **独自メソッドを絡める**：「体感軸調整法」など自店の視点を必ず1箇所以上。汎用コピペにしない（E-E-A-T／独自性）。
7. **内部リンク**：本文中に該当 `/symptoms/*` への文脈リンク、`related` に2〜3本、CTAは ColumnLayout が自動。

### 3-2. 分量・トーン
- 目安 **1,500〜2,500字**（意図を満たすのに必要な分だけ。薄い増量はしない）。
- 一人称は「当店」。押し売りせず、まずセルフケアで役立つ情報を出し切る→最後にプロの価値を添える。

### 3-3. ファイルの作り方（実装）
コラムは `src/pages/column/<slug>.astro` に1ファイル。`ColumnLayout` を使う。**新設の `faq` プロップに必ず3〜5問**を渡す。

```astro
---
import ColumnLayout from '../../layouts/ColumnLayout.astro';
---
<ColumnLayout
  slug="<slug>"
  title="<SEOタイトル｜32〜40字・主要KW前方＋【岐阜市長良のストレッチ専門店】>"
  description="<120字前後・主要KWと便益・地域を自然に>"
  heading="<h1／titleより短い読者向け見出し>"
  datePublished="YYYY-MM-DD"
  related={[
    { label: '○○でお悩みの方へ（当店のアプローチ）', href: '/symptoms/xxx' },
  ]}
  faq={[
    { q: '<質問1>', a: '<40〜120字の簡潔な回答>' },
    { q: '<質問2>', a: '<...>' },
    { q: '<質問3>', a: '<...>' },
  ]}
>
  <p><strong>結論先出しのリード（30〜60字の答え）。</strong>続けて背景1〜2文。</p>

  <h2>なぜ○○は起きる？</h2>
  <p>...</p>

  <h2>自分でできる○○ストレッチ</h2>
  <h3>1. △△（20秒×左右）</h3>
  <p>...</p>

  <h2>セルフケアの限界と当店のアプローチ</h2>
  <p>...<a href="/symptoms/xxx">○○向けのパーソナルストレッチ</a>...</p>
</ColumnLayout>
```

### 3-4. タイトル/ディスクリプションの型
- **title**：`<主要KWを前方に>｜<便益や具体>【岐阜市長良のストレッチ専門店が解説】` （全角32〜40字目安、地域名を含める）
- **description**：主要KW＋悩み＋便益＋地域を自然文で120字前後。煽らない。

## 4. 自動生成セッションの手順（ルーティンが実行）

ルーティンが新規セッションを起動したら、以下を順に行う：

1. `docs/AI_CHANGELOG.md` と本ガイドを読む。**コラム専用ブランチ `claude/column-auto`** を用意する：`git fetch origin` → 既にあれば checkout して `origin/claude/zenkara-gifu-nagara-seo-ukz0er`（本番）へ rebase、無ければ `origin/claude/zenkara-gifu-nagara-seo-ukz0er` から作成。※デザイン作業ブランチとは分ける（コラムだけを独立してレビュー・公開できるように）。
2. `docs/column-backlog.md` の未対応（`- [ ]`）から**最上位の1件**を選ぶ。既存 `src/pages/column/*.astro` と意図が被らないか確認。
3. 本ガイド 3章のテンプレに従い、`src/pages/column/<slug>.astro` を作成（**faq 必須**、内部リンク必須、独自視点必須）。
4. `src/data/columns.ts` の `COLUMNS` 配列の**先頭**に新記事を追加（slug / heading / desc / date / tags / relatedSymptoms）。この配列は `/column` 一覧と `/content.json`（SNS運用システム向け構造化データ）の両方の単一ソース。
5. `npm run build` が通ることを確認（19→20ページに増える）。
6. `docs/column-backlog.md` の該当行を `- [x]` に更新。`docs/AI_CHANGELOG.md` に作業記録を追記。
7. **公開方法（下記5章）に従ってコミット／プッシュ。**
8. 1回のセッションで**1本のみ**作成（品質担保）。

---

## 5. 公開方法（レビュー運用）

- **既定：レビューしてから公開。** 生成物はコラム専用ブランチ `claude/column-auto` にコミット＆プッシュし、**ユーザーが確認して本番ブランチ `claude/zenkara-gifu-nagara-seo-ukz0er` へマージ**（＝公開）。健康系の事実担保・ブランド保護のため。**本番ブランチへ自動マージはしない。**
- 全自動にする場合のみ、`claude/column-auto` を本番ブランチへマージまで行う（品質チェックリストを厳守できる場合に限る）。

- [ ] 医療効果を断定していない（免責はレイアウトが付与）。
