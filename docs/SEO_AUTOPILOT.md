# SEO自動運転システム設計書（全力ストレッチ岐阜長良店）

作成: 2026-08-07 ／ 状態: Phase 1 実装済み（同日E2E検証済み・PR #26で初の全自動公開）

動画で語られる「7プロセスの自動運転」を本サイト向けに設計したもの。
ただし目標は動画の「月20万PV」ではなく「**岐阜商圏で予約につながる検索流入の最大化**」に置く
（理由は末尾「§8 正直なキャリブレーション」参照）。

## §2 全体アーキテクチャ

```
                    ┌─────────────────────────────────────┐
                    │  データ層（windsor-data ブランチ）      │
                    │  毎朝8:00 GitHub Actions が取得        │
                    │  GA4 / Google Ads / Meta / ★GSC追加   │
                    └──────────────┬──────────────────────┘
                                   │ git読み（MCP不依存）
   ┌───────────────┬───────────────┼────────────────┬─────────────┐
   ▼               ▼               ▼                ▼             ▼
[P2+P3 補充]   [P4 執筆]      [P5 品質GATE]    [P6 分析]     [P7 リライト]
keyword-       column-        column-auto内    週次レポート    column-
replenish.yml  auto.yml       lint+AIレビュー   Routine(月曜)   rewrite.yml
月1回・月初     月水金9:00      生成の直後       SEO section    週1回・火曜
   │               │               │                │             │
   │  バックログ     │  記事PR        │ PASS→自動マージ  │ リライト指令  │ 改善PR
   └──→ docs/column-backlog.md      │ FAIL→修正1回→  │ (JSON)      │
                                    │ それでもNGなら   └──────→──────┘
                                    │ 人間へ通知
                    ┌───────────────▼──────────────────────┐
                    │        本番ブランチ → Vercel 自動デプロイ  │
                    └──────────────────────────────────────┘
```

原則：
- **読み取りは全部git経由**（windsor-data中継）。MCP接続断に依存しない。
- **各ワークフローは独立**。1つ死んでも他は回る。
- **品質GATEを通らない記事は公開されない**。量産時の事故防止はここで担保。
- 人間（オーナー）の関与は「通知への対応」と「月次の方向性確認」のみ。

## §3 P2+P3: キーワード補充ワークフロー（keyword-replenish.yml・月1）

バックログ残24件 ≒ 2ヶ月分。枯渇する前に月初に自動補充する。

### データ入力
- GSC 90日: query / page / impressions / clicks / position
- 既存記事一覧（src/pages/column/）と既存バックログ（重複防止）
- docs/COLUMN_SEO_GUIDE.md 2章（キーワード方針: 3〜4語ロングテール）

### プロンプト（claude-code-action に渡す）

```
あなたは岐阜市のパーソナルストレッチ専門店のSEO戦略担当です。
docs/COLUMN_SEO_GUIDE.md と docs/keyword-map.md を読み、方針に従ってください。

入力データ:
- data/gsc_90d.json（検索クエリ実績）
- docs/column-backlog.md（既存バックログ）
- src/data/columns.ts（公開済み記事）

タスク: 新しい記事ネタを10件発掘し、バックログ形式で追記する。

発掘の優先順位:
1. 【取りこぼし】GSCで表示回数があるのに、対応する記事が無いクエリ
   （impressions>50 かつ 既存記事のタイトル・見出しにないもの）
2. 【惜しい】掲載順位11〜30位のクエリの周辺トピック（記事を足すと面で強くなる）
3. 【季節】今後2ヶ月の季節文脈（例: 9月なら「秋 ゴルフ 前 ストレッチ」「季節の変わり目 だるさ」）
4. 【地域】「岐阜」「長良」を含む地域複合（type: local）

制約:
- キーワードは3〜4語のロングテール。1〜2語のビッグワードは禁止。
- 症状ページ（/symptoms/*）のどれかに内部リンクできるネタのみ。
- 医療・治療を約束するテーマは不可（薬機法）。「〜のセルフケア」「〜との付き合い方」の角度で。
- 既存記事・既存バックログと意図が重複するものは除外。
- 形式: `- [ ] slug ｜ authority|local ｜ キーワード ｜ 記事タイプ ｜ 内部リンク先`

出力: docs/column-backlog.md への追記コミットのみ。記事は書かない。
最後に、追加した10件それぞれについて「なぜ今これか」を1行ずつPRコメントに書く。
```

## §4 P5: 品質GATE（column-auto.yml に組み込み・2段構え）

現在は「生成 → PR → セッション内で人間+AIがチェック → マージ」。属人性を排除して
ワークフロー内で完結させる。

### 第1段: 機械チェック（scripts/lint-column.mjs・新規）

決定的なルールはAIに任せない。落ちたらこの時点で修正指示へ。

```
チェック項目（exit 1 で失敗）:
- 薬機法NGワード: /治る|治療|治り|効果があ|改善し(ま|た)|解消|矯正|効く|効きま|
  完治|即効|No\.?1|絶対|必ず.{0,6}(良く|回復)|根本改善/
- 画像がAI/フリー素材の場合に「※画像はイメージです」表記があるか
- imageAlt に「当店」「自店」「施術中」等、自店写真と誤認させる語が無いか
- 内部リンク href が実在するページか（src/pages/ を走査）
- columns.ts にエントリが追加されているか / slugの一意性
- FAQが3問以上あるか / datePublished が今日か
- npm run build が通るか
```

### 第2段: AIレビュー（同ワークフロー内の2回目のclaude呼び出し）

```
あなたは薬機法・景表法に厳格なレビュアー兼、検索意図の編集者です。
生成された記事 {file} を読み、以下をJSONで判定してください。

1. compliance: 機械チェックをすり抜ける文脈的な効能断定が無いか
   （例:「痛みが消えていく」「二度と戻らない体へ」のような婉曲断定）
2. intent: タイトルのキーワードで検索する人の疑問に、冒頭200字で答えているか
3. eeat: 「岐阜市長良の専門店のトレーナーが解説」の立場が一貫しているか。
   一般論の寄せ集めになっていないか（体感軸調整法への自然な言及が1箇所以上）
4. safety: 医療機関への受診を促すべき症状の線引きがあるか

出力: {"verdict":"PASS"|"FAIL","fixes":[{"line":n,"reason":"...","suggestion":"..."}]}
FAILの場合、fixesを自分で適用して再コミットし、lintを再実行。
2回目もFAILなら、マージせずPRに「要人間確認」ラベルを付けて終了。
```

### マージ規則
- PASS → ワークフローが自動マージ（現在私が手動でやっている部分の自動化）
- FAIL×2 → 通知して人間へ。**量産時に事故が「公開されない」ことを保証する**

## §5 P6: 分析（既存の週次レポートRoutineへSEOセクション追加）

### データ追加（scripts/fetch-windsor-data.mjs に4クエリ追加）
- gsc_28d: query/page/impressions/clicks/position（Windsorの google_search_console コネクタ。**要接続**）
- gsc_90d: 同上90日（キーワード補充用）
- ga4_columns_28d: /column/* のPV・エンゲージメント・セッション経由CV

### 週次レポートの分析プロンプト（月曜Routineに追記する断片）

```
SEOセクション: git show origin/windsor-data:gsc_28d.json 等を読み、
1. 記事別スコアボード: clicks / impressions / CTR / position / 前週差分
2. 分類:
   - WINNER: position≦10 かつ clicks増 → 何もしない（触らない）
   - OPPORTUNITY: position 5〜20 かつ impressions≧100 かつ CTR<3%
     → タイトル/description リライト候補
   - UNDERPERFORMER: 公開後8週以上 かつ clicks<5 → 本文リライトor統合候補
   - CANNIBALIZATION: 同一クエリに2記事が出ている → 統合候補
3. リライト指令の発行: 上位2件を data/rewrite-queue.json に書き出しコミット
   {"slug":"...","reason":"OPPORTUNITY","queries":[上位クエリ10件],"action":"title|body|merge"}
```

判断基準はコードではなくプロンプトに置く（閾値の調整が会話で済むように）。

## §6 P7: リライトワークフロー（column-rewrite.yml・週1火曜）

### トリガー: data/rewrite-queue.json にエントリがある場合のみ実行

### プロンプト

```
あなたは検索順位改善の専門編集者です。docs/COLUMN_SEO_GUIDE.md と
docs/yakkihou-ng-ok.md の制約下で、既存記事をリライトします。

入力: data/rewrite-queue.json の先頭エントリ
- 対象: src/pages/column/{slug}.astro
- 実際に表示されている検索クエリ: {queries}

action=title の場合（CTR改善）:
- title/description のみ変更。本文は触らない。
- 実クエリの語を含め、数字・具体性で押す（例:「5選」「1日3分」）。
- 32文字以内にキーワードを収める。誇大表現・釣りタイトル禁止。

action=body の場合（順位改善）:
- 実クエリのうち記事が答えていない疑問を特定し、h2セクションを1〜2個追加。
- 既存の文章は壊さない（追記と部分修正のみ）。FAQに実クエリ由来の質問を追加。
- 冒頭の要約段落を、最多クエリへの直答に書き換え。
- dateModified を今日に更新。

action=merge の場合:
- 弱い方の記事から強い方へ内容を統合し、弱い方は301リダイレクト
  （astro.config.mjs の redirects に追加）。

完了後: 品質GATE（lint+AIレビュー）を通し、PASSなら自動マージ。
処理したエントリは rewrite-queue.json から削除してコミット。
リライト前後のtitle/主要変更点をPRコメントに記録（効果測定は4週後の分析が拾う）。
```

### 安全弁
- リライトは**週2記事まで**（Googleの再評価には2〜4週かかる。一気に全部触ると因果が分からなくなる）
- WINNERは触らない（改悪防止）
- 同一記事の再リライトは前回から28日以上空ける

## §8 正直なキャリブレーション（動画の前提との違い）

1. **「月20万PV」は全国ボリュームのニッチ（補助金）の数字。** 本サイトは
   「岐阜×ストレッチ×症状」の地域商圏で、検索母数の上限が桁で違う。
   現実的な当面の目標: **6ヶ月でオーガニック月3,000〜8,000セッション、
   そこからの予約アクション月30〜50件**（=広告費換算で月10〜15万円分の集客を無料化）。
2. **「月100記事」はこのニッチでは逆効果。** トピック総数がそこまで無く、
   薄い記事の量産はHelpful Content観点でサイト全体の評価を下げる。
   週3〜5本 × リライトループの方が同じ労力で上に行く。
3. **健康系はYMYL隣接。** 品質GATEの薬機法チェックは飾りではなく、
   量産時の最大リスク（行政指導・広告アカウント停止）への保険。
4. 動画の主張で正しい部分: **「書いて終わり」と「測って書き直す」の差は本物。**
   本設計の価値の8割はPhase 2〜4（GSC→分析→リライト）にある。
```

## 運用ステータス追記（2026-08-11）

- **Search Console接続済み**：Windsorのスラッグは `searchconsole`（google_search_console等ではない）。プロパティ https://zn-stretch-gifu.com/
- **コネクタの制約**：ページ単位（page/pagepath）の内訳が取れず、サイト合計に丸められる。クエリ単位（query×clicks/impressions/ctr/position）は正常。ページ別の深掘りが必要な場合はGSC管理画面を直接見る
- データリレーに `gsc_queries_28d` / `gsc_queries_prev28d` を追加済み。週次レポートはこの2つを比較して
  WINNER（順位上昇・クリック増）/ OPPORTUNITY（表示多いのにCTR低い）/ UNDERPERFORMER（順位下落）を分類し、リライト候補を提示する
- リライト基準：公開8週間経過して表示回数が伸びない記事はタイトル・見出しを見直す
